# Secret Rotation

> Sprint 4D (ADR-014). Secrets live in `deploy/production/.env` on the VM
> (generated by `generate-secrets.sh`, `chmod 600`). Rotation is manual and
> documented; nothing is committed and nothing has a `change-me` default.

## Preconditions

- Working VM access + `deploy/production/.env`.
- Commands below read values like `$POSTGRES_USER` from the shell. `.env` is
  not auto-sourced, so export them first:
  `cd deploy/production && set -a && source .env && set +a`.
- Save the **new** values (and, briefly, the old ones) in your password
  manager before applying them — a half-applied rotation is the common failure.

## JWT secret

The most frequently rotated credential (compromise = forgeable tokens).

```sh
cd deploy/production
NEW=$(openssl rand -hex 32)
# record NEW; then swap the value in .env (sed or $EDITOR)
docker compose up -d gateway          # gateway picks up the new secret
# Old refresh tokens are invalidated. Users re-login; no DB step needed.
```

Note: rotating the JWT secret signs out every active session — schedule it as
a maintenance window.

## PostgreSQL

1. Generate a new password and update `.env` (`POSTGRES_PASSWORD`).
2. Apply it inside Postgres (as the existing superuser):
   ```sh
   docker compose exec postgres \
     psql -U "$POSTGRES_USER" -d postgres -c \
     "ALTER USER \"$POSTGRES_USER\" WITH PASSWORD 'NEW';"
   ```
3. Restart the app services that pool DB connections so they reconnect with
   the new credential:
   ```sh
   docker compose up -d --force-recreate gateway worker scheduler
   ```
4. Update the backup jobs that use the old credential.

## RabbitMQ

```sh
docker compose exec rabbitmq rabbitmqctl change_password "$RABBITMQ_USER" 'NEW'
# update .env (RABBITMQ_PASS), then:
docker compose up -d --force-recreate gateway worker scheduler
```

## MinIO (object store)

```sh
# `mc` lives in the minio-init service (minio/mc image), which is one-shot, so
# use `run` (not `exec`); -e VAR passes the .env value through:
docker compose run --rm --no-deps \
  -e MINIO_ROOT_USER -e MINIO_ROOT_PASSWORD \
  minio-init mc alias set local http://minio:9000 "$MINIO_ROOT_USER" "$MINIO_ROOT_PASSWORD"
# rotate root creds via env + restart (root user password lives in env):
#   update .env MINIO_ROOT_PASSWORD (and S3_SECRET_KEY = same), then:
docker compose up -d --force-recreate minio minio-init gateway worker scheduler
# S3 clients reconnect on the next presigned/upload call.
```

## Grafana (overlay only)

Update `GRAFANA_ADMIN_PASSWORD` in `.env` and restart grafana
(`docker compose -f docker-compose.yml -f observability.yml up -d grafana`).

## Registry credential (GHCR pull, ADR-014/016)

Not in `.env`. Rotate by issuing a new GitHub PAT, then on the VM:

```sh
echo "$NEW_TOKEN" | docker login ghcr.io -u <user> --password-stdin
# persists in ~/.docker/config.json on the VM (chmod 600).
```

## After any rotation

- `docker compose config` still exits 0 (all `${VAR:?}` secrets present).
- App services healthy: `docker compose ps`.
- API smoke: `curl -sf https://api.<SITE_DOMAIN>/health/ready`.
